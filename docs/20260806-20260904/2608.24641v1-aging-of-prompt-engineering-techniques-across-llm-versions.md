## 摘要
提示工程和提示工程技术已成为AI系统软件工程不可或缺的一部分。然而，新的大语言模型频繁发布，提示工程技术在不同代际的大语言模型之间的有效性如何变化仍不清楚。为此，我们对Khojah等人（2025）的研究进行了部分复制。我们在六种指令调优模型上评估了五种技术——零样本、少样本、思维链、对比思维链以及改编版的程序思维——这些模型被分为三个版本对：GPT-3.5-Turbo/GPT-4o、Qwen2 7B Instruct/Qwen2.5 7B Instruct 和 Mistral-7B-Instruct/Mistral-Large。我们使用CodePromptEval数据集中的一个清理子集，包含218个上下文丰富的Python函数，并通过基于pass@k的功能正确性评估了总共19,620次生成，以评估模型对在函数级代码生成任务上的表现。我们证明，提示工程以特定于模型家族的方式“老化”：较新的GPT模型从结构化提示中获得的边际收益递减甚至为负，这表明指令遵循和推理支架日益被内化，而Qwen模型继续从少样本和对比思维链中显著受益。Mistral模型表现出混合行为，从对比思维链中获得持续收益，但从思维链和程序思维中的收益则减弱。我们的结果表明，有效的提示策略必须针对每个模型家族和代际进行调整，而非不变地转移。这为未来关于自适应、模型感知的提示以及更广泛、多维度的代码质量评估的研究提供了动力。

## Abstract
Prompt engineering and prompt engineering techniques (PETs) have become an integral part of software engineering for AI systems. However, new LLMs are released frequently and it remains unclear how the effectiveness of prompt engineering techniques changes across successive generations of Large Language Models (LLMs). To this end, we conduct a partial replication of the study by Khojah et al. (2025). We evaluate five techniques - Zero-Shot, Few-Shot, Chain-of-Thought (CoT), Contrastive Chain-of-Thought (CCoT), and an adapted version of Program-of-Thought (PoT) - on six instruction-tuned models grouped into three version pairs: GPT-3.5-Turbo/GPT-4o, Qwen2 7B Instruct/Qwen2.5 7B Instruct, and Mistral-7B-Instruct/Mistral-Large. We use a cleaned subset of the CodePromptEval dataset with 218 context-rich Python functions and 19,620 total generations assessed via pass@k-based functional correctness to evaluate model pairs on function-level code generation tasks. We show that prompt engineering "ages" in a model-family-specific way: Newer GPT models exhibit diminishing or even negative marginal gains from structured prompting, suggesting that instruction-following and reasoning scaffolds are increasingly internalized, whereas Qwen models continue to benefit substantially from Few-Shot and CCoT. Mistral models show mixed behavior with persistent gains from CCoT but attenuated benefits from CoT and PoT. Our results imply that effective prompting strategies must be adapted per model family and generation rather than transferred unchanged. This motivates future work on adaptive, model-aware prompting and broader, multi-dimensional code quality evaluation.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）以极快的速度迭代更新，提示工程技术（Prompt Engineering Techniques, PETs）已成为面向 AI 系统的软件工程实践中不可或缺的组成部分。然而，提示策略的有效性是否随 LLM 代际更新而保持不变，尚缺乏系统性认识。
- **核心问题**：当用户从旧版模型迁移到同系列的新版模型时，原本有效的提示技巧（如少样本、思维链等）是否依然有效？其边际价值是在增长、衰减还是消失？是否存在“提示工程老化（aging of prompt engineering）”现象？
- **整体含义**：若不同模型家族对提示工程的依赖模式不同，则提示策略不能简单跨模型迁移，需要针对具体模型家族与代际进行自适应调整。该研究对这一实际问题给出了首个系统性经验证据。

## 2. 方法论

- **核心思想**：对 Khojah et al.（2025）的 CodePromptEval 研究进行**部分复制（partial replication）**，聚焦“提示工程有效性随 LLM 版本如何变化”这一新研究问题，以函数级代码生成的功能正确性（pass@k）为衡量标准。
- **提示工程技术（PETs）**：共评估五种技术——
  1. **Zero-Shot**：仅提供编码任务与单代码块输出要求，作为基线。
  2. **Few-Shot**：在任务基础上附加两个输入–输出示例对。
  3. **Chain-of-Thought (CoT)**：指示模型“逐步思考、逻辑推理后再作答”。
  4. **Contrastive Chain-of-Thought (CCoT)**：在 CoT 基础上，额外提供两个**正面推理示例**和两个**错误推理示例**。负例通过实体识别模型（spaCy en_core_web_trf）抽取正确推理中的核心对象（关键变量、数字、函数名、常量如 None/True/False），然后随机打乱其位置生成。
  5. **Adapted Program-of-Thought (PoT)**：在 CoT 模板中增加指令“Use code to express all reasoning steps”，要求模型用代码形式表达全部推理步骤（由于原任务是代码生成，对原始 PoT 做了任务适配）。
- **实验流程**：
  1. 从 CodePromptEval 提取 654 个原始 prompt，另新建 436 个，共 1,090 个 prompt（每种 PET × 218 个任务）。
  2. 用六个模型对 1,090 个 prompt 各生成 3 次响应，共 19,620 个输出（温度 0.2，最大 token 限制 1024）。
  3. 自动提取 markdown 代码块中的代码（失败时手动提取），因提取失败剔除 23 个 prompt 的全部生成，最终评估数据集为 17,550 个函数、195 个有效任务。
  4. 沿用原 CoderEval Docker 环境和 CodePromptEval 评估方法，计算 **pass@1、pass@2、pass@3**。
- **分析方式**：以零样本为基线，计算每种 PET 相对于基线的通过率变化（Δ%），并对同一家族的前后两代模型做差异对比，以描述性统计为主。

## 6. 主要结论与发现

- **提示工程“老化”呈模型家族特异性**，不存在可跨代跨模型迁移的通用最优提示策略：

| 模型家族 | 主要模式 |
|---------|---------|
| **GPT** | 新版（GPT-4o）对结构化提示出现**饱和效应**——Few-Shot（平均 −7.4 pp）、CoT（−0.8 pp）的增益为负或接近零，CCoT 仅微增（+1.1 pp），PoT 小幅改善（+4.2 pp）但绝对性能仍低于基线。指令跟随与推理支架日益被模型内化。 |
| **Qwen** | 新版（Qwen2.5）持续从提示工程中获益——Few-Shot（+7.9 pp）与 CCoT（+11.5 pp）均呈显著正增益；pass@k 多采样分析中 CCoT 在 pass@1/2/3 上分别有 +10.0、+13.4、+11.6 pp 的稳健提升。 |
| **Mistral** | 混合表现——CoT（−13.8 pp）与 PoT（−12.1 pp）在大模型上转负，呈现类似 GPT 的“内化/饱和”；但 **CCoT 依然稳健有效**（+5.6 pp），Few-Shot 基本持平（+0.8 pp），说明带显式正/反例的提示仍然提供增量价值。 |

- **具体技术层面**：
  - **Few-Shot**：对小/弱模型（Mistral-7B、GPT-3.5）增益显著，但在多采样（pass@3）下增益饱和甚至逆转——示例主要用于任务消歧，而非提供额外多样性；
  - **CoT**：在新版 GPT 与 Mistral-Large 上不仅冗余甚至有害，新模型已将逐步推理内化；
  - **CCoT**：是唯一在三大家族中均显示正增益的技术，显式正/反比对缓解自由形式 CoT 的噪声有效；
  - **PoT**：在代码生成场景表现出架构相关的不稳定性，其从数学推理任务迁移到真实代码生成时收益不能直接复制。
- **对实践的启示**：采用新模型时必须重新评估提示策略，不能假设既有“配方”仍然有效；对研究者的启示是需发展**自适应的、模型感知的提示策略**。

## 7. 优点

- **研究问题新颖且切中时弊**：首次系统比较提示工程有效性在同一模型家族不同代际间的演变，回应“模型变强是否意味着不再需要提示工程”这一争论。
- **复制 + 扩展的规范研究设计**：遵循 Carver 的复制报告规范（明确列出与原始研究的延续与变更），提供了表 I 所示的清晰对比清单；且在同一模型（GPT-4o）上做了与原始研究的一致性验证，既检验了复制的可靠性，又扩展了 CCoT、PoT 等原研究未覆盖的技术。
- **模型选择严谨**：以训练截止日期早于数据发布、可追溯的版本谱系等标准筛选模型，尽力规避数据泄漏并保证同家族代际对比的合理性。
- **控制与归因清晰**：以 Zero-Shot 为统一基线，逐次输出与逐 k 值（pass@1/2/3）多层报告，方便区分技术真实效应与采样波动；发现了“采样次数增加后 Few-Shot 增益饱和”等细致模式。
- **分析中肯**：对结果差异给出了方法论层面的合理解释（如技术定义、任务域差异、解码配置、模型规模失配等），并坦诚讨论了对结论效度的影响。
- **开放科学**：提供完整复制包（含数据与脚本），支持后续研究的验证与扩展。

## 8. 不足与局限

- **外部效度受限**：仅评估 Python 函数级生成任务（CodePromptEval / CoderEval），结论未必适用于其他编程语言、文件/项目级代码生成或真实生产环境。
- **指标单一**：只度量功能正确性（pass@k），未纳入可维护性、安全性、效率、代码异味等多维质量指标，可能遗漏提示技术对代码质量维度的差异化影响。
- **统计功效不足**：每条件仅 3 次生成，且无显著性检验；LLM 采样非确定性较大，小样本使结论的置信区间较宽，削弱了差异判定的稳健性。
- **模型规模与格式混淆**：
  - Mistral-7B（7B）与 Mistral-Large（123B）规模差异悬殊，提示“老化”效应无法与规模效应剥离；
  - Mistral-7B 需 [INST] 包裹 prompt 而 Mistral-Large 直接处理 raw prompt，格式不一致可能影响家族内对比公平性。
- **数据泄漏风险未能完全排除**：尽管以训练截止日期在 CoderEval 发布之前为筛选条件，但处于训练截止时间线上的数据有可能成为预训练语料的小部分来源；且中间尺寸的 Mistral 后继模型不可得，削弱了“同架构、同时代、仅规模变化”的理想对比条件。
- **技术适配的限制**：PoT 的“改写为 use code to express all reasoning steps”是一种改编而非原始方法本身，其与原始 PoT 的差异可能影响结论对比；且所有 PET 均为静态单轮提示，未纳入迭代式/批判式提示（如自我修正、多轮反馈）等更进阶策略。
- **应用限制**：研究呈现的是规律性描述而非最优策略推荐——对于“如何在某个特定新模型上选择最优提示”，尚未给出可用机制或自动化选择工具，实用价值有待后续的模型感知自适应提示框架推进。
