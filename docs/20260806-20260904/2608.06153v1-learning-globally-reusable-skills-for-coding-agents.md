## 摘要
自动化技能演化使大型语言模型（LLM）代理能够在不进行昂贵重新训练的情况下持续改进。然而，现有方法通常将技能演化视为一系列局部更新，忽视了技能之间的关系，并常常产生过拟合的技能更新，无法跨任务泛化。我们提出GSE，一种全局化的技能演化框架，联合优化技能兼容性和技能泛化。为了保持技能库的一致性，GSE维护一个技能关系图（SRG），显式建模并共同演化技能间关系。为了提高泛化性，GSE执行基于聚类的技能整合，从局部更新中抽象可复用能力，并采用重放驱动的验证来防止过拟合和行为回归。我们在两个代表性的软件工程任务上评估GSE：揭示缺陷的测试生成和误报缺陷报告过滤。在两个最先进的编码代理OpenHands和mini-SWE-agent上，GSE始终取得最佳精确率、召回率和F1分数。与现有演化技术相比，GSE在测试生成方面将精确率和召回率提高了6.1%~34.1%和31.8%~180.0%，在误报过滤方面提高了15.4%~96.4%和13.1%~19.8%。在内部工业代理上的部署进一步使F1分数提高了61.4%，证明了GSE在演化有效技能方面的有效性和泛化性。

## Abstract
Automated skill evolution enables Large Language Model (LLM) agents to continuously improve without expensive retraining. However, existing approaches typically treat skill evolution as a sequence of local updates, overlooking relationships among skills and often producing overfitted skill updates that fail to generalize across tasks. We propose GSE, a globalized skill evolution framework that jointly optimizes skill compatibility and skill generalization. To preserve consistency across the skill bank, GSE maintains a Skill Relation Graph (SRG) that explicitly models and co-evolves inter-skill relationships. To improve generalization, GSE performs cluster-based skill consolidation to abstract reusable capabilities from local updates and employs replay-driven verification to prevent overfitting and behavioral regressions. We evaluate GSE on two representative software engineering tasks: bug-revealing test generation and false-positive bug report filtering. Across two state-of-the-art coding agents, OpenHands and mini-SWE-agent, GSE consistently achieves the best precision, recall, and F1-score. Compared with existing evolution techniques, GSE improves precision and recall by 6.1%~34.1% and 31.8%~180.0% for test generation, and by 15.4%~96.4% and 13.1%~19.8% for false-positive filtering. Deployment on an internal industrial agent further yields a 61.4% improvement in F1-score, demonstrating the effectiveness and generalizability of GSE for evolving effective skills.

## 论文总结：学习面向编码代理的全局可复用技能（GSE）

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在软件工程任务中，基于LLM的编码代理（如自动测试生成、缺陷分析）通常依赖静态的技能库，难以适应复杂多变的代码库和任务。为持续提升代理性能，自动化技能演化成为一种关键手段，但现有方法存在两大缺陷：
    - **缺乏全局视野**：将技能演化视为单个轨迹上的独立局部更新，忽略了技能之间的依赖、互补或冲突关系，导致技能库内部逐渐不兼容、行为冲突。
    - **泛化性差**：从单一执行轨迹中提取的局部更新极易过拟合到特定项目、特定缺陷模式，难以形成高质量、可复用的通用能力，长期来看会损害技能库的整体效果。
- **论文整体含义**：本文提出一种全局化技能演化框架 **GSE**，将技能演化从一系列局部更新提升为**对技能库进行全局优化**的过程。通过显式建模技能关系并抽象泛化局部更新，GSE所演化的技能具有更好的兼容性和可复用性，能够为代理带来持续且稳定的性能提升。

### 2. 论文提出的方法论

**核心思想**：不同于以往“生成提案 -> 直接合并”的流水线，GSE将技能库视为一个相互连接的可复用系统，同步优化技能内容及其关系，并通过聚类整合与重放验证来确保技能并非仅对特定用例有效，而是具备泛化的抽象能力。

**GSE 框架概览（如图1所示）**：

- **过程从“轨迹收集”开始**：为捕获代理真实的执行历史，GSE 首先对任务运行轨迹进行**精简**处理，过滤掉大量低价值的工具输出如 `grep/find` 全量结果、原始文件内容、编译反馈等，仅保留命令元数据、关键错误信息及代理的内部推理步骤，保留高层次的因果逻辑。
- **演化提案生成（Evolution Proposal Generation）**：
    - **失败诊断**：对失败案例进行分层诊断，归因于导航（上下文探索缺陷）、推理（代码理解缺陷）或执行（终端行为缺陷）问题，并区分两类演化方向：**通用能力增强** 与 **可复用问题模式（bug pattern）的固化**。
    - **技能关系图（SRG, Skill Relation Graph）**：以有向图形式显式建模技能间的三种关系：`Dependency`（依赖关系）、`Co-usage`（协同使用）、`Conflict`（冲突关系）。基于该图，GSE 在提出主演化提案时同步分析相关技能，生成**辅助演化提案**，共同更新受影响的技能及关系，确保全局一致性。
    - **DSL结构化提案**：使用定义明确的领域特定语言（DSL）结构化表达操作类型、目标技能、更新内容、理由、预期效果和关系修改，使提案便于后续处理。
    - **局部验证**：将提案应用于临时技能库，重放失败轨迹以确保解决原始失败；不通过的提案会被较早排除。
- **技能泛化（Skill Generalization，Algorithm 1）**：
    - **基于聚类的技能整合（Consolidation）**：将经过局部验证的提案聚类（依据影响技能集合或语义相似性），从每簇提取共同能力模式并去重，合并形成更高层级的技能抽象，避免冗余和碎片化。
    - **重放驱动的验证（Replay-driven Validation）**：对抽象候选技能，在相关历史案例上整体重放。若整体效果能维持或提升，则接受该抽象技能，否则直接丢弃，以杜绝过拟合与回归退化。

### 3. 实验设计

- **Base Agent**：在两种主流开源编码代理上验证，包括 **OpenHands** 和 **mini-SWE-agent**（并进行技能加载轻量扩展）。
- **对比方法**：与**手工编写的专家技能（Human Skills）**、两种最先进的演化框架 **Live-SWE-agent** 和 **Trace2Skill**，以及没有任何技能的**基础代理（Base Agent）** 进行对照。
- **核心测量指标**：对两种任务均使用 `Precision`、`Recall`、`F1-score` 进行评估（测试生成中所有焦点方法本身有缺陷，因此不存在 true negative；误报过滤中按标准分类处理）。评价协议采用**单项目留出法**，确保演化阶段不接触到待评估的任务实例。

### 6. 论文的主要结论与发现

- **主要结论1（测试生成）**：GSE 在测试生成任务上远超其它基线。相比效果最好的局部演化基线，GSE 在 OpenHands 上提升 F1 分数 40.9%（0.22 → 0.31），在 mini-SWE-agent 上提高 31.0%（0.29 → 0.38），且能生成既精确又具有高覆盖率（不误报）的缺陷揭示测试。
- **主要结论2（误报过滤）**：在误报过滤任务中，GSE 大幅抑制了误报（高精确率），并保持高召回。相比最强基线，OpenHands 上 F1 提升约 62.8%（0.43 → 0.70），mini-SWE-agent 上提升约 17.9%（0.39 → 0.46）。

### 7. 优点

- **独到的研究切入点**：没有局限于技能演化局部生成，而是以**全局化**的视角审视技能库相互协作关系，成功解决了因兼容性缺失而导致的严重退化问题。
- **模型设计的完整性**：通过 SRG 将技能系统显式建模、将知识关系作为一等公民进行同步演化，这是一种超越单纯动作提示的有深度的知识组织机制。
- **机制层面有很强的可靠性**：泛化抽象（聚类）+ 面向历史的重放验证，如同加入了机器学习中“批处理”和“验证集”两重安全护栏，同时完成了模型的“数据增强”与“抗过拟合”。
- **应用方向贴近真实工业软件流程**：评测不只拘泥于benchmark，同时涵盖行业需求（误报标签的过滤、工业误报治理），扩大了工作问题映射范围。

### 8. 不足与局限

- **任务广度和语言覆盖有限**：实验主要集中在 Java/Go 这两个语言、聚焦‘测试生成’和‘缺陷报告过滤’两大任务，尚不足以证明 GSE 在更广泛的软件工程任务（如修复代码、代码评审）或其它语言上依然有效。
- **可转移性的量化验证仍有盲区**：作者精心使用了单项目留出法，但若要评估演化技能的真正跨任务可迁移性（跨任务，例如从生成测试演化出的技能迁移到 Bug 修复），在测试中未侧重体现明确量化支撑。
- **领域知识与人工标注权重较高**：人工评估并筛选出可触发 bug 的焦点方法，这可能引入人工建议带来的主观操作残留，影响数据的一致纯净度。
- **用户定义技能库初始状态的敏感性**：实验依赖预设某些人工技能来触发演化，那么在技能库刚起步很小或完全为空时，GSE 尚无法明确呈现其初始收敛速度和效果相较于其它初始化的差别。
- **消融实验的泛化瑕疵**：在 A/B 实验中只基于 OpenHands，未能测试在 mini-SWE-agent 上是否会因基线执行风格不同导致对核心模块依赖程度的改变。
- **生产环境具体收益未公开明细**：工业实际部署选择了误报过滤这一指标比较高的任务，而在高噪声低生成式命中的基线环境中是否始终正向也没有完整的展开分析。
