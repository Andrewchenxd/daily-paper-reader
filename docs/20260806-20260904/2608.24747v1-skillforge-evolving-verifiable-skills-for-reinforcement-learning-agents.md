## 摘要
大规模语言模型（LLM）智能体通过强化学习（RL）训练以完成复杂决策任务。然而，大多数经过RL训练的智能体仍然是情节性的，无法跨情节累积可重复使用的知识。近期基于技能的方法（如SkillRL）尝试通过从原始轨迹中提取技能来解决这一问题，但将技能库视为仅追加的存储库，而不验证存储的技能是否仍然有效。在本文中，我们提出了SkillForge，一个用于持续技能进化的框架，使技能能够通过环境交互得到验证和精炼。通过在智能体交互过程中显式化技能使用，RL可以直接优化环境动作和技能调用决策。SkillForge进一步引入了基于证据的技能验证和多路径技能归纳，使技能库能够在保持质量的同时持续增长。在ALFWorld、WebShop和AppWorld上的大量实验表明，SkillForge始终优于SkillRL，展示了持续验证技能在训练更强大LLM智能体方面的有效性。

## Abstract
Large language model (LLM) agents are trained with reinforcement learning (RL) for complex decision-making tasks. However, most RL-trained agents remain episodic and cannot accumulate reusable knowledge across episodes. Recent skill-based approaches, such as SkillRL, attempt to address this issue by extracting skills from raw trajectories, but treat the skill bank as an append-only repository without verifying whether stored skills remain effective. In this paper, we propose SkillForge, a framework for continuous skill evolution that enables skills to be verified and refined through environment interaction. By making skill usage explicit during agent interaction, RL can directly optimize both environment actions and skill invocation decisions. SkillForge further introduces evidence-based skill verification and multi-pathway skill induction, allowing the skill bank to continuously grow while maintaining its quality. Extensive experiments on ALFWorld, WebShop, and AppWorld show that SkillForge consistently outperforms SkillRL, demonstrating the effectiveness of continuously verified skills in training stronger LLM agents.

- **背景事实**：大规模语言模型（LLM）智能体通过强化学习（RL）训练来处理复杂决策任务，但绝大多数 RL 训练出的智能体是 **“情节性”（episodic）** 的——每个回合都从零开始，无法跨回合积累和复用知识，导致有效行为被反复“重新发现”，学习效率低下。
- **现有解决方案的不足**：已有工作（如 SkillRL）尝试从原始轨迹中蒸馏出可复用的“技能”并注入策略提示，但其本质是 **“只追加”（append-only）的技能库**——技能一经写入便很少再被审视，无法验证技能是否依然有效。
- **具体三大局限**：
  1. **技能使用不可观测**：技能被批量注入提示，无法判断智能体是否真正依赖某一技能做决策；
  2. **技能效果难以归因**：缺少显式的技能使用信号，难以确定成功轨迹是否由特定技能导致；
  3. **技能质量不可控**：错误或过时的技能可能永久停留在库中，逐渐污染整个知识库。

**整体含义**：论文主张技能不应是静态的记忆条目，而应作为可通过环境交互被持续验证、精炼和更新的“可演化能力”，从而真正支持智能体的跨回合知识积累。

## 二、方法论（SkillForge）

### 1. 核心思想
同时优化策略权重与技能库，通过 **显式技能调用**，让 RL 能对技能使用进行直接优化和“信用分配”；通过 **证据验证 + 多路径归纳**，让技能库在扩张的同时保持质量。

### 2. 技能表示与检索（§3.1）
- **技能结构**：每个技能是一个结构化元组 `(title, intent, principle, applicability, category, status)`，其中：
  - `title` 为可调用标识符；
  - `intent` 为用途简述；
  - `principle` 为核心决策策略；
  - `applicability` 为适用条件；
  - `category` 分为 `general` 与 `task-specific`；
  - `status` 标记 `active / under-review / deprecated`。
- **技能库初始构造**：先用初始指令微调策略在环境中 rollout，再用教师 LLM 将成功轨迹蒸馏为策略模式、失败轨迹合成为纠正性经验，形成两层级（通用 + 任务类别）初始技能库。
- **检索与目录注入**：基于 embedding 语义相似度对任务描述做 top-K 技能检索，提示中仅展示紧凑目录（技能名 + 单行触发描述），全文内容则留到被显式调用后再返回——从而将提示长度与库大小解耦。

### 3. 显式技能调用与策略优化（§3.2）
- 每一步智能体输出由环境动作与可选技能调用组成：`a_t = (a_t^{env}, c_t)`，其中 `c_t ∈ {∅} ∪ S_ret`，以结构化 `<skill_call> NAME </skill_call>` 标签发出。
- 技能调用被当作轨迹中的**离散、可追踪事件**，技能使用因此可观测、可归因，且由于该标签属于生成的 token，RL 可**联合优化环境动作与技能调用决策**。
- 策略优化采用 **GRPO** 算法，利用组内相对优势对动作和技能调用统一进行策略梯度优化，并带 KL 约束。
- 轨迹经 LLM **抽象压缩**后，按成败分为 `T+` 和 `T−` 缓冲区，供归纳使用。

### 4. 多路径技能归纳（§3.3）
每 `I` 步由教师 LLM 基于轨迹抽象合成新技能，按轨迹分布选择三种路径之一：
- **抽取（extraction）**：从成功轨迹提取通用策略；
- **精炼（refinement）**：从失败轨迹识别反复出现的失败模式并形成矫正策略；
- **对比分析（contrastive）**：成对比较成败轨迹，识别行为上的决定性差异。

新技能在加入前经**词汇匹配 + 语义相似度**双重去重。

### 5. 基于证据的技能验证
- 维护每个技能的 **EMA 成功率**：`p_s ← α·r + (1−α)·p_s`；
- 综合 EMA 成功率与使用次数构成**低表现分数**：`conf(s) = (1−p_s)·(1−0.5·n_s/h)`，其中 `h` 为使用半衰期；
- 高 conf 的技能说明有更强证据表现不佳，被优先送入 **LLM Reflexion**，由教师模型结合近期使用上下文裁决 `keep` 或 `revise`（重写 principle 与适用条件）。

### 6. 整体训练循环（Algorithm 1）
交替进行：技能增强的 rollout → GRPO 策略更新 → 统计更新；每隔 `I` 步执行一次技能库维护（归纳、去重、验证、反思），更新后的库立即用于后续 rollout，形成“生成-测试-精炼”闭环。

## 六、主要结论与发现

1. **SkillForge 一致超越 SkillRL**：
   - 在不做冷启动 SFT、相同 Qwen2.5-7B 下，ALFWorld 成功率 +3.7，WebShop 成功率 +10.3，AppWorld 的 TGC 从 19.0 提升到 23.8、SGC 从 5.36 提升到 14.3；
   - 使用 Qwen3-30B-A3B 时可达到最高成绩（ALFWorld 94.3；AppWorld TGC 59.5）。
2. **技能确实在“进化”**：技能库从初始 44 条稳步增长至 90 条左右，且 t-SNE 显示新技能不断覆盖新的语义区域，代表技能在反思中从粗略规则演化为精确、具备更强验证条件的策略。
3. **技能具有跨模型迁移性**：小模型演化到后期的技能库表现优于早期技能库，甚至接近或超过大模型“自进化”的技能库。
4. **学习过程受显式调用约束**：SkillForge 开始时因学习调用技能略慢，但随后收敛更快、渐近性能更高。
5. **总结性论点**：持续验证与精炼技能能有效提升 RL 智能体在开放环境中的决策能力，为“技能驱动型”智能体的构建提供了可行范式。

## 七、方法亮点

- **显式技能调用机制**设计精巧：将“技能使用”从隐式上下文转化为结构化离散事件，使 RL 能直接优化技能选择，并得到细粒度的技能级信用分配/有效性反馈；
- **验证闭环（证据追踪 + Reflexion）**：用 EMA 成功率与使用量自动计算“低表现”分数，让技能库不再盲目膨胀，而是“有质量门槛”的演化；
- **多路径技能归纳**：不只从成功轨迹抽取，还从失败轨迹与成败对比中提炼纠正性知识，知识来源覆盖更全面；
- **无需 SFT 初始化**：相比 SkillRL（SFT+RL 两阶段），只用 RL 即可生效，管道更简洁；
- **分析实验设计合理**：包含 teacher

## 八、局限性与潜在缺点（综合论文自述与本文观察）

### 1. 论文明确承认的局限
- **任务生命周期仍需人为预设训练目标**：技能的归纳与验证仍依赖每回合奖励，未探讨开放式的、奖励稀疏/无奖励场景下技能如何演化；
- **技能调用机制停留于“文字标签”层面**：目前以 token 形式随动作一起输出并由 LLM 解析，本质上仍属于策略内部的隐式协议，而非真正“模块化”的独立技能执行单元（如代码函数、外部 API 或独立子策略）；
- **技能验证的最终仲裁者是教师 LLM**：虽然 EMA 统计提供了量化证据，但 `keep / revise` 的最终裁决依赖 Qwen3-Max 等外部模型的判断，框架质量的天花板仍受教师能力制约；
- **技能查询依赖语义检索**：在长任务链条、状态高度同质或任务描述模糊的场景下，检索的 Top-K 召回质量可能成为瓶颈，论文未对此边界做深入测试。

### 2. 本文视角下的进一步观察
- **证据有效性度量偏“单向”**：EMA 成功率只反映“用过之后是否成功”，却难以区分“这一技能是成功的主要原因”与“技能被调用但其实是可有可无的伴随行为”之间的差别，因果归因颗粒度仍不够细（不过显式调用已比隐式注入向前迈了一大步）；
- **Deprecated 技能的命运未充分讨论**：技能被降级后是否会被物理移除？若不移除，长期运行后库的冗余度如何控制；论文对技能淘汰机制的细节着墨不多；
- **同环境内任务的难度构成可能存在分布偏移**：技能库的“演化”究竟是在积累对新任务分布的新知识，还是在将已有知识固化得更精确？两种效应并未被严格分解测量；
- **对比基线的公平性仍有微小存疑**：SkillRL 使用了额外的 SFT 预热阶段，SkillForge 纯粹依靠 RL 便超越之，这固然是亮点；但同时也意味着两者在训练总预算、数据使用量上的对齐方式需要更透明的成本等价说明。

## 九、总体评价与延伸思考

### 1. 这是一篇“问题找得准、工程闭环完整”的工作
论文没有停留在“给 LLM 加记忆”的浅层方案，而是直指记忆型技能库三大弊病（不可观测、不可归因、不可控），并用一套“显式调用 → 轨迹证据 → 多路径归纳 → 反思修订”的闭环框架作出回应。从完成度上看，它是目前该方向上机制设计最完整、实验最系统的实证工作之一。

### 2. 最具启发性的两个设计决策
- **“把技能调用当作可被 RL 优化的离散动作”**：这一选择同时解决了可观测性、可归因性与可学习性三个问题，是对“经验如何进入策略”这一核心难题的一句话解法；
- **“用成功率证据驱动技能反思”**：将技能库从静态资产变为动态种群，既防了“坏技能带偏策略”（deprecated 机制），又防了“好技能被埋没”（成功轨迹持续被抽取）。这实质是把**进化论式的选择压力**引入知识管理，是全文思想浓度最高的部分。

### 3. 未来可能的延展方向
- 将技能调用抽象为**真正的模块化子程序**（子策略 / 代码片段），而非文本指示，使技能可在不同主干模型间直接执行而不依赖语义理解；
- 将证据验证从“结局成败”推进到“**过程可解释性**”：例如结合内部注意力或值函数信号，判断技能在轨迹中的边际贡献；
- 探索技能库与训练数据的**互相增强式闭环**（如主动收集更能区分技能好坏的对抗性任务），让“验证”的灵敏度不依赖于任务分布的自然出现；
- 把 EMA 证据与“**技能年龄**”“**环境概念漂移**”结合，让技能像生物免疫系统一样进行周期性“自检与记忆细胞更新”，进一步降低知识过时的风险。

### 4. 一句话评价
> SkillForge 的价值不在于提供了一套更聪明的 RL 训练技巧，而在于给出了一种**让智能体的经验具备“科学方法”气质**的训练范式——提出假设（技能）、控制变量（显式调用）、收集数据（证据跟踪）、检验并修正假设（Reflexion）。它把“记忆”从被动存储的档案柜，变成了主动生长、自我纠错的知识生命体。
