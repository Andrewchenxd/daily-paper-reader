## 摘要
技能进化通过随时间推移的反馈来提升智能体技能，其中失败的轨迹往往能通过揭示不完整或误导性的行为提供有价值的信息。然而，现有方法主要依赖单一轨迹，早期推理错误可能传播到后续步骤，削弱可用于技能优化的反馈。因此，改进技能需要反复进行展开、诊断和更新的循环，造成大量token开销。为解决这一挑战，我们引入了Branch2Skill，一种高效框架，将单个推理树转化为用于技能进化的密集监督。对于每个任务或问题，Branch2Skill在固定预算下执行蒙特卡洛树搜索以获得多样化的推理轨迹，然后将精英路径与共享相同前缀的兄弟替代路径进行比较，提取关于哪些推理模式应保留、修正或避免的逐步证据。最后，Branch2Skill将多步证据提炼为可复用的更新，使一个推理树能够为多个推理步骤提供监督，并减少重复展开-更新循环的需求。在涵盖推理和智能体任务的六个基准上，Branch2Skill持续提升任务性能，同时提高技能进化效率。例如，以GPT 5.5作为目标模型时，Branch2Skill相比SkillOpt减少了73.2%的token消耗，同时实现了更优性能。这些结果表明，推理树不仅能支持更有效的轨迹搜索，还能为更高效的技能改进提供更丰富的监督。代码将公开发布。

## Abstract
Skill evolution improves agent skills through feedback over time, with failed trajectories often providing informative signals by revealing incomplete or misleading behaviors. However, existing methods mainly rely on single trajectories, where early reasoning errors can propagate through subsequent steps and weaken the feedback available for skill refinement. Consequently, improving skills requires repeated cycles of rollout, diagnosis, and update, incurring substantial token costs. To address this challenge, we introduce Branch2Skill, an efficient framework that transforms a single reasoning tree into dense supervision for skill evolution. For each task or problem, Branch2Skill performs Monte Carlo tree search under a fixed budget to obtain diverse reasoning trajectories, then compares an elite path with sibling alternatives sharing the same prefixes to extract step-wise evidence about which reasoning patterns to retain, revise, or avoid. Finally, Branch2Skill distills multi-step evidence into reusable updates, allowing one reasoning tree to provide supervision across multiple reasoning steps and reducing the need for repeated rollout-update cycles. Across six benchmarks covering reasoning and agentic tasks, Branch2Skill consistently improves task performance while enhancing skill evolution efficiency. For example, with GPT 5.5 as the target model, Branch2Skill uses 73.2% fewer tokens than SkillOpt, while achieving superior performance. These results demonstrate that reasoning trees can support not only more effective trajectory search, but also richer supervision for more efficient skill improvement. Code will be published.

# Branch2Skill：通过推理树实现高效的技能进化——论文详细中文总结

## 一、核心问题与研究动机

- **背景**：LLM 智能体需要在多任务中通过积累经验不断改进自身能力。但直接微调模型参数成本高、不现实，因此业界倾向于将经验“外部化”为可复用的技能（skill），并基于执行反馈持续修订技能。
- **核心问题**：
  - 现有技能进化方法大多依赖**单条轨迹**（single trajectory）的失败反馈。单条轨迹中，早期推理错误会沿后续步骤传播，导致大部分后续步骤的反馈不可靠，真正可用于技能修正的信号往往只有一个。
  - 因此，要获得新的反馈信号，就必须重新进行 rollout → 诊断 → 更新，**token 开销巨大、监督稀疏**。
  - 需要一种方法，让一次探索过程就能提供**多个步骤、多个局部决策**的密集监督，从而打破反复采样-更新循环的成本瓶颈。
- **核心洞察**：
  - 蒙特卡洛树搜索（MCTS）可以生成一个推理树，树中兄弟节点共享相同前缀，仅在当前决策点分叉。比较“精英路径”与共享前缀的兄弟分支，能够将下游结果差异局部归因于**该深度处的决策**，无需额外的错误归因模型。
  - 一次推理树搜索不仅能找到更优轨迹，还能同时为多个推理步骤提供“应保留/修改/避免”的证据，进而用于更新持久技能。

## 二、方法：Branch2Skill

- **总体框架**：以固定的离散更新步（update step）迭代进化自然语言技能。每步取 M 个训练问题，在**当前技能固定不变**的前提下，对每个问题独立构建推理树；搜索结束后汇总证据，由“技能模型”修改技能；最后用**固定验证集**做门控（validation gate）决定是否接受修改。
- **核心角色**：
  - **目标模型（target model）**：负责生成推理节点，并对节点打分数（评估前缀成功概率）。
  - **技能模型（skill model / optimizer）**：根据推理树提取的证据，用 Append / Replace / Delete 操作改写现有技能。
- **关键步骤**：
  1. **逐步行推理树构建**：
     - 根节点表示基于当前问题和技能的空路径；非根节点只含一个推理步骤或环境动作。
     - 扩展时，目标模型基于当前前缀生成最多 C 个候选后继。
     - 节点选择采用 PUCT 公式：
       \[
       \text{PUCT}(u,v) = Q(v) + c_{\text{puct}} \cdot \frac{P(v|u)\sqrt{\max(1,N(u))}}{1+N(v)}
       \]
       其中 \(Q(v)\) 为 v 的反向传播平均分，\(N(\cdot)\) 为访问次数，\(P(v|u)\) 为子节点先验概率。
     - 每个子节点生成后，目标模型对完整前缀进行标量进度评分（self-assessment），并反向传播更新祖先节点。
     - 搜索受迭代预算 I、最大深度 \(D_{max}\)、子节点数 C 等约束。接近预算/深度时强制完成路径，避免产生无终端结果的中间节点；搜索后，尚未终止的非叶前缀会被补全一次，以获得终端结果。
  2. **共享前缀证据提取**：
     - 保留一条“精英路径” \(\pi^*\)；若树中有成功路径则优先选择，否则挑最强失败路径。
     - 对精英路径上的每个深度 d，收集共享父节点的兄弟集合 \(B_d\)。
     - 每个证据项包含：共享前缀、被选步骤、少量兄弟节点及其下游结果、搜索统计信息。**不把整棵推理树发给技能模型**。
     - 由于兄弟节点前缀相同，分歧仅来自当前决策，因此其结果差异能提供局部、无歧义的监督信号。
  3. **技能修订与验证**：
     - 将每步中 M 棵树的证据聚合，发送给技能模型，一次输出完整候选技能。支持三种操作：
       - **Append**：增加缺失的规则、条件或前置步骤；
       - **Replace**：修正动作、对象、条件或范围冲突的指导；
       - **Delete**：删除误导、冗余或反复关联失败分支的指导。
     - 验证门控：固定验证集 V 上直接推理（无树搜索），分别评估旧技能和候选技能。若候选技能在所有指定指标上都不低于旧技能，则接受，否则回滚。
       \[
       K_{t+1} = \begin{cases}
       \hat{K}_{t+1} & g(\hat{K}_{t+1}; V) \succeq g(K_t; V) \\
       K_t & \text{otherwise}
       \end{cases}
       \]
     - 保留验证性能最佳的 checkpoint 做最终评估。

## 六、主要结论与发现

- **性能提升**：Branch2Skill 在 30 个设置中排名第一或并列第一的有 26 个，超越 SkillOpt 的有 27 个；平均分从无技能的 50.8 提升到 69.1，超过 SkillOpt 的 66.0。
- **token 效率巨大提升**：在 GPT-5.5 上，总 token 从 526.7M 降到 141.3M，减少 73.2%；总测试增益从 117.8 增至 128.7，提高 9.3%；每百万 token 的增益从 0.224 增至 0.911，提升 4.07 倍。
- **模型间交互效应**：更强的技能模型（GPT-5.5）在数学推理（LiveMath）上显著提升所有目标模型的表现；SearchQA 对技能模型能力较不敏感，说明分支证据在不同模型间可迁移。
- **消融结论**：更大的搜索容量（更深、更多子节点、更多迭代）带来稳定提升；证据选择方法至关重要——共享前缀兄弟证据远优于单路径和整棵树（LiveMath 上分别提升约 13.7 和 15.3 个百分点），证明局部对比是技能更新的关键。
- **迁移性**：冻结技能可跨模型迁移（LiveMath 最多提升 21.6 点），也可从 OlympiadBench 迁移到 Omni-MATH（提升约 2.8–3.5 点），表明学到的是通用程序而非样例记忆。
- **整体意义**：推理树不仅是更高效的测试时搜索工具，更可转化为多步密集监督源，显著提升技能进化的效率与效果。

## 七、方法/实验优点

- **新范式**：将“搜索树 → 轨迹搜索”提升为“搜索树 → 多步密集技能监督”，回答了“如何让一次失败反馈产生多个动作”的问题。
- **因果定位自然性**：利用树结构天然的共享前缀兄弟关系，无需额外错误定位模型，避免了单轨迹中后续步骤的误导性继承。
- **降低 token 开销**：一个推理树即可为多个决策点提供对比证据，显著减少 rollout-更新循环次数。
- **验证门控机制**：在固定验证集上的非退化测试保证了技能持续累积，防止短视修改损害整体效用。
- **实验设计广度**：5 种目标模型 × 6 个任务、25 种模型交互、跨模型/跨数据迁移、多维消融，展示了方法的鲁棒性与通用性。
- **清晰的可视化与图表**：通过 ALFWorld 案例直观说明同父兄弟如何暴露不同错误模式。
