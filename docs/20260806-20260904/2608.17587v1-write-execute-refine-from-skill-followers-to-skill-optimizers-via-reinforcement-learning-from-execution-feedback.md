## 摘要
专家编写的自然语言技能可以改善使用工具的智能体，但智能体自行编写的技能比不使用技能表现差8-11个百分点。这一差距表明，遵循程序性指导与根据执行证据改进指导是两种不同的能力。推理时循环可以修复技能，但无法改进编写下一个技能的模型。我们研究了如何将中间技能产生的执行经验组织成优化器的训练状态。我们引入了WER（编写、执行和完善）框架，这是一个多阶段框架，在冻结的执行器之外训练技能优化器。优化器提出技能，冻结的智能体重复执行每个技能，程序化验证器对结果进行评分。分数提供相对信用并选择混合结果记录。这些记录中匹配的成功与失败轨迹构成下一阶段的完善状态，因此优化器能从其早期输出的后果中学习。在BFCL v4多轮和tau2-bench上，WER将平均Pass@1相对于无技能基线分别提高了7.80和3.85个百分点。在相同的完善流程下，它比未经过优化器训练的相同骨干模型高出9.35和10.29个百分点。训练后的4B优化器在BFCL v4上达到76.63%的准确率，超过所有作为技能优化器进行评估的现成通用模型的平均表现。

## Abstract
Expert-written natural language skills can improve tool-using agents, yet agent-authored skills perform 8-11 points worse than using no skill. This gap suggests that following procedural guidance and improving it from execution evidence are distinct capabilities. Inference time loops can repair skills but do not improve the model that writes the next one. We study how to organize execution experience from intermediate skills into training states for an optimizer. We introduce WER (Write, Execute, and Refine), a multi-phase framework that trains a Skill Optimizer outside a frozen executor. The optimizer proposes skills, a frozen agent executes each repeatedly, and a programmatic verifier scores the outcomes. The scores provide relative credit and select mixed-outcome records. Matched successful and failed trajectories from these records form the next phase's refinement states, so the optimizer learns from the consequences of its earlier outputs. On BFCL v4 multi-turn and tau2-bench, WER improves average Pass@1 over the no-skill baseline by 7.80 and 3.85 points, respectively. Under an identical refinement workflow, it outperforms the same backbone without optimizer training by 9.35 and 10.29 points. The trained 4B optimizer reaches 76.63 percent on BFCL v4, outperforming all evaluated off-the-shelf general-purpose models used as skill optimizers on average.

- **核心现象**：专家撰写的自然语言技能（skill）能显著提升工具使用智能体的表现（在SkillsBench上，平均通过率从33.9%提升至50.5%），但智能体自行撰写的技能反而比完全不使用技能还低8-11个百分点。

### 2. 方法论：WER框架

#### 2.1 总体架构

WER（Write, Execute, and Refine）包含三个实体：

- **Skill Optimizer（πθ）**：待训练的小型策略模型（4B Qwen3-4B），存在于环境外部，唯一输出是一个技能文档。
- **冻结的Executor（πA）**：被固定、不可训练的工具使用智能体（GPT-4o），技能被注入其系统提示词。
- **程序化验证器**：确定性、非模型化的评判者（如环境状态比对）。

流程为：优化器提出技能 → 冻结智能体重复执行 → 验证器打分 → 分数提供组内相对信用 → 混合结果记录配对成下一阶段的细化状态。

#### 2.2 细化状态（Refinement State)的定义

一个细化状态表示为：x = (q, C, h, s, e)，其中q是用户查询，C是工具定义与环境描述，h是交互历史，s是当前技能，e是该技能上次运行产生的执行证据。优化器的生成规则为：s′ ∼ πθ(· | x)。

#### 2.3 两条观察通道

- **轨迹作为上下文**：轨迹不被摘要化，原封不动传达给优化器。只有完整轨迹才能告诉优化器"哪里需要修改"——例如看到同一调用重复三次针对已失效的ID，说明技能未要求智能体在执行前检查状态。
- **结果作为奖励**：是否成功由环境/验证器决定（BFCL v4比较最终环境对象状态与参考解状态，τ2-bench比较终端数据库与参考数据库）。不使用模型评分，避免模型自我确认陷阱。

#### 2.4 奖励与优化

奖励函数由三项平均构成：

**R(s′) = (1/3)(Rfmt + Rtask + Rlen)**

- Rfmt：格式合规性（推理块与技能体分离），训练中逐渐退火（早期学到后不再与任务项竞争）
- Rtask：n次rollout的验证器结果聚合
- Rlen：推理块长度约束（惩罚空推理与超预算）

#### 2.5 阶段式自举（Phase-Wise Self-Bootstrapping)

这是WER方法的核心创新点，包含三个环节：

- **经验缓冲**：每次评分的候选以(x, s′, {τ1...τn}, R)元组记录，保留全部轨迹而不只聚合值。
- **选择性留存**：以n=2次rollout为例，候选得分可为0、1、2。仅保留得分恰好为1（混合结果）的记录。这样同一技能在同一任务上的一次成功与一次失败形成对照对——技能与任务固定，轨迹差异仅出现在技能未约束的分支处，差异本身即为需要修改的地方。
- **状态组装**：下一阶段状态通过拼接而非摘要构建。成功轨迹放入成功块、失败轨迹放入失败块，当前技能为s，工具上下文C从原任务恢复。阶段推进时，优化器被要求改进自己上一轮产出的技能，形成"修订树"而非从初始草稿重启。

整体训练过程如Algorithm 1：对每个阶段，从细化状态采样K个候选技能、各执行n次、计算奖励与优势、更新策略、留存混合结果并组装下一阶段状态。

### 6. 主要结论与发现

- WER相对No Skill基线将BFCL v4平均Pass@1从68.83%提升至76.63%（+7.80点），τ2-bench从46.87%提升至50.72%（+3.85点）。
- 同一细化流程下，训练后的Qwen3-4B比未训练骨干高9.35点（BFCL v4）与10.29点（τ2-bench），证明执行反馈到有效技能的转化能力确实可以被训练。
- 4B参数的WER-trained优化器在BFCL v4上达到76.63%，超过所有评估的通用模型作优化器的成绩（最高为GPT-5.5的74.75%），表明技能修细能力不能完全被通用推理能力覆盖。
- 阶段式自举确实是有效的：每个阶段的输入分布来自早期阶段自身输出，训练多轮细化能力不可由单阶段替代。
- 推理时大仅2轮细修即基本饱和，更多轮次收益递减。

### 7. 方法亮点

- **冻结执行器保证信用归属**：只有冻结执行器时，同一细化状态下两个候选结果的差异才能归因于技能文档本身。联合训练执行器虽然分数更高，但会瓦解这一信号。
- **验证器与模型评分解耦**：程序化验证而非模型评分，有效防范自我确认陷阱，切断了质量信号与产生行为的模型家族之间的混淆。
- **混合结果选择性留存设计精巧**：n=2时仅保留得分1的记录。配对成败轨迹在固定任务与技能条件下形成受控对比（成功路径展示可行分支，失败路径展示技能未排除的分支），单条轨迹无论成败都无法精确定位缺口。
- **组相对优势处理任务难度差异**：绝对结果跨任务差异大，但组内比较排除了任务难度干扰。
- **"不同阶段训练不同深度"的设计哲学**：细化深度成为训练而非推理的属性——通过多阶段反复实践，策略可以学到深度修细能力，推理时自由选择轮数。

### 8. 不足与局限

- **验证器依赖**：方法目前仅在拥有程序化验证器的环境中得到验证（BFCL v4、τ2-bench）。开放任务、开放式评估、无程序化验证器的场景下是否有效尚不明确。
- **执行器单一**：评估仅使用GPT-4o一个冻结执行器，未验证换用其他执行器（如不同规模的模型）后的泛化表现。
- **种子技能来源单一**：初始技能全部由GPT-5.1生成，模型对起始草稿风格的鲁棒性未知。
- **轨迹原样保留导致伸缩性问题**：后续细化状态的上下文随任务长度增长而线性变大。长程任务、多模态轨迹、大规模技能库场景下可能出现上下文瓶颈。
- **数据集规模较小**：两个benchmark均为约200个任务的小型测试集（虽然各评估三次取平均以降低方差），但对统计功效和泛化推断有所限制。
- **混合结果依赖n的选择**：留存策略依赖n=2的rollout配置，n变化时（如n=3）如何选择留存记录未展开讨论。
