## 摘要
智能体技能将专业知识和流程封装为可复用的资源，从而扩展AI智能体的能力。近期工作从智能体经验中自动发现此类技能，使智能体能够通过交互逐步适应。然而，指导技能开发的洞见通常分散在优化历史中，限制了其在多次迭代中的系统复用。我们提出了WikiSkill，一个将智能体技能与持久知识库（wiki）共同进化的框架。在高层面上，WikiSkill将原始执行经验、积累的知识和可执行技能分离，同时持续将经验整合到wiki中，后续的技能更新可在此基础上构建。在多种基准和模型上，WikiSkill一致地优于最先进的技能进化方法，并在大多数模型-基准设置中优于无技能基线。我们发现技能进化与模型规模互补：较大的模型通常从进化技能中获益更多，而具有技能的较小模型可以超越没有技能的显著较大的模型。我们还发现，进化技能在模型和模型家族之间能够有效迁移，且由其他模型进化的技能可能优于自我进化的技能。最后，我们的消融研究证实，wiki中持久知识的积累对于有效的技能进化至关重要。这些结果证明了系统地积累和提炼智能体经验对于开发可复用和可迁移技能的价值。

## Abstract
Agent skills package specialized knowledge and workflows into reusable resources that extend AI agent capabilities. Recent work automatically discovers such skills from agent experience, which enables agents to progressively adapt through interaction. However, the insights that guide skill development typically remain scattered across optimization histories, limiting their systematic reuse across iterations. We introduce WikiSkill, a framework that co-evolves agent skills with a persistent knowledge base (wiki). At a high level, WikiSkill separates raw execution experience, accumulated knowledge, and executable skills, while continuously consolidating experience into the wiki, which subsequent skill updates can build on. Across diverse benchmarks and models, WikiSkill consistently outperforms state-of-the-art skill-evolution methods and improves over no-skill baselines in most model-benchmark settings. We find that skill evolution complements model scaling: larger models generally benefit more from evolved skills, while smaller models with skills can outperform substantially larger models without them. We also find that evolved skills transfer effectively across models and model families, and skills evolved by other models can outperform self-evolved skills. Finally, our ablation studies confirm that persistent knowledge accumulation in the wiki is critical for effective skill evolution. These results demonstrate the benefits of systematically accumulating and refining agent experience for developing reusable and transferable skills.

## 1. 核心问题与研究动机

- **背景**：通用 AI 智能体已具备处理复杂跨域任务的能力，但真实世界任务往往需要领域特定的专业知识、流程与工作流。Agent Skills（技能）以轻量、开放、基于文件系统的方式封装这类专业知识（如 SKILL.md 指令、脚本等），可在不修改模型参数的情况下扩展能力，支持跨智能体重用、可审计和渐进式披露。
- **核心问题**：当前技能大多依赖人工编写，难以预先穷尽智能体所需流程；自动技能发现方法（如 EvoSkill、Trace2Skill、SkillOpt）虽然能从执行轨迹中学习，但指导技能演化的洞察（失败模式、成功策略、尝试历史等）通常散落在优化历史中，没有形成独立、持续演化的知识表示，难以在多次迭代中被系统性复用和累积。
- **核心挑战**：如何将智能体经验"编译"为持久化的、可累积的知识，使其能够支持长期、跨迭代的技能演化，而非每次从碎片化历史中重新开始。论文受 Andrej Karpathy 关于"LLM Wiki"观点的启发，提出知识应像 wiki 一样不断沉淀与复利式成长。

## 2. 方法论：WikiSkill 框架

### 2.1 核心思想

- 在原始执行经验与可执行技能之间增加一层"结构化知识层"（**Wiki 层**），实现**三层知识架构**的分离：
  - **Raw Layer（raw/）**：存储不可变的原始执行轨迹，保留完整历史；
  - **Wiki Layer（wiki/）**：持久化、可累积的知识库，不随迭代重置，包含 patterns、index、logs.md（演化日志）、skill-impact.md（技能影响审计）；
  - **Skill Layer（skills/）**：可演化的程序性技能集合，包含 SKILL.md 和 PURPOSE.md。

### 2.2 演化循环

每轮迭代由四个组件构成，形成持续闭环：

1. **Inference Agent（推断智能体）**：基于当前技能集在训练集上执行 rollout，产生轨迹到 raw/。训练期间禁止访问 Wiki（消融实验证明允许访问会降低最终技能质量，因任务解决知识可能直接来自 wiki 而非技能，使轨迹对技能演化信息量降低）。
2. **Wiki Maintainer（Wiki 维护者）**：对采样轨迹（每轮最多 8 条：5 条失败 + 3 条成功）进行根因分析，提取成功策略，以增量 patch 方式创建或更新 pattern 页面，并更新 index 目录和 logs.md。
3. **Skill Proposer（技能提议者）**：以 ReAct 方式运行，先读取 wiki 索引、skill-impact.md 和训练结果摘要，再按需用 read_file 工具探索具体 pattern 页和原始轨迹，每次产出一个原子化提案（创建新技能或对现有技能做增量 patch 编辑）。
4. **Gating and Rollback（门控与回滚）**：将候选技能在验证集上评估，若验证得分显著提高则接受并更新最佳阈值；否则回滚技能集到上一版本。**wiki 永远不会被回滚**，即使提案被拒绝，其 diff、得分与结果也会程序化写入 skill-impact.md，防止后续重复已失败的尝试。

### 2.3 关键公式

执行轨迹、知识整合、提案生成与门控接受规则如下：

- 轨迹：𝜏ᵢ ~ 𝜋(𝑥ᵢ; Sₖ₋₁)
- Wiki 整合：W′ₖ ← M_WM(Wₖ₋₁, T_sample,ₖ)
- 技能提案：Pₖ ← M_P(W′ₖ, Sₖ₋₁, T_train,ₖ)
- 门控接受规则：
  - Sₖ = S′ₖ，若 R(T_val,ₖ) > R_best
  - Sₖ = Sₖ₋₁，否则
- 算法在验证得分达到 1.0 时提前终止。

## 6. 主要结论与发现

1. **WikiSkill 一致优于既有技能演化方法**：在各模型上的平均准确率比最强竞争方法分别提高 3.3–12.0 个百分点，且在大多数模型-数据组合中优于无技能基线。例如 Gemini-3.5-Flash 在 LiveMath 从 33.0% → 72.6%，Qwen-3.6-27B 在 SpreadSheet 从 40.8% → 81.7%。
2. **技能演化与模型规模互补**：
   - 模型越强，从技能中获益越多（Qwen 家族：4B 提升 12.3%、9B 提升 17.5%、27B 提升 23.9%）；
   - 小模型配技能可超越无技能的更大模型：Qwen-3.5-9B + WikiSkill（47.4%）> Qwen-3.6-27B 无技能（39.4%）。
3. **技能可跨模型迁移，甚至优于自我演化**：ALFWorld 上 Qwen-3.5-9B 使用 Qwen-3.6-27B 演化的技能达 70.2%，优于自演化技能的 63.4%；较小源模型（Qwen-3.5-4B）也能产出对较大模型有效的技能（如将 Gemma-4-31B 的 LiveMath 提升至 73.1%）。
4. **迁移效果取决于技能是通用过程还是模型特定变通**：LiveMath 技能迁移好；SpreadSheet 中 Qwen-3.5-4B 技能包含低层 workaround，反而使 Gemini-3.5-Flash 从 50.5% 降至 18.1%（负迁移）。
5. **持久 Wiki 知识积累是关键**：给 Skill Proposer 提供持久 wiki 使平均性能提高 15.0%（从 48.7% → 63.7%）；而训练时让 Inference Agent 访问 wiki 反而将平均性能从 63.7% 降至 60.9%。
6. **日志审计机制有效**：被拒提案的完整 diff 被保留，避免重复失败提议；案例研究显示第 0 轮被拒的过于抽象的 goal-directed-action 促使第 1 轮产出更具体、可接受的 break-repetition-loop，并在第 4 轮由新模式证据驱动进一步精化。

## 7. 优点

- **知识架构设计新颖**：将"原始经验 → 结构化知识 → 程序性技能"三级分离，wiki 层作为持久化、不断沉淀的知识载体，解决了既有方法中知识碎片化、无法跨迭代持续复用的问题；
- **接受/拒绝过程的可审计性**：skill-impact.md 记录每个提案的完整 diff、验证得分与接受结果，使演化过程透明且具解释性；
- **回滚技能但保留 wiki 的设计**：在被拒提案中保留知识，避免重复试错，支持后续提案基于更完整上下文做更明智决策；
- **深入揭示技能演化与模型能力的内在关系**：模型规模互补效应、跨模型迁移（含从较小模型到较大模型的正迁移）、以及"发现技能"与"执行技能"是两种不同能力的区分，具有启发意义；
- **实验设计较扎实**：多次独立运行、paired bootstrap 显著性检验、与既有方法严格的设置对齐；
- **复杂度分析**：在方法比较中加入了优化器调用复杂度分析，并单独分析了各框架的调用计数，透明地说明计算特点。

## 8. 不足与局限

- **未覆盖技能检索与触发**：为隔离技能质量变量，全程将技能全文直接注入提示，未评估当技能库扩大时如何检索/选择技能（论文明确承认此局限）；
- **严格门控排除了中性提案**：若某提案不立即提升验证分数但可能在后续迭代中产生收益，会被直接拒绝，缺少更灵活的接受标准；
- **Wiki 缺乏自动修剪机制**：长期演化中 pattern 与日志不断累积，可能出现信息过载或知识冗余，需要定期压缩或淘汰策略；
- **任务范围有限**：未覆盖数百步环境动作级别的超长任务，也没有评估在单次长执行中在线自适应调整技能的能力；
- **对负迁移现象仅做初步分析**：虽指出 Qwen-3.5-4B 技能导致 Gemini-3.5-Flash 在 SpreadSheet 上的性能大幅下降，但对如何自动判定或避免跨模型负迁移缺少机制层面的解决方案；
- **消融覆盖不足**：消融（Inference Agent 的 Wiki 访问影响等）只在 Gemini-3.5-Flash 上验证，无法确认是否在所有模型中结论一致；
- **模型与数据集的时效性**：论文涉及 2026 年的新模型与新基准，结论的普遍性有待后续更广泛验证。
