## 摘要
自我进化的智能体通过基于环境反馈优化其装备（提示、技能、工具和执行逻辑）来迈向自主性。然而，这一范式受到三个挑战的阻碍：\textit{信用分配失败}，即终端成功/失败反馈使得难以确定哪个步骤导致了错误；\textit{捷径学习}，即智能体记忆任务特定模式而非获得可泛化的能力；以及\textit{灾难性遗忘}，即无保护的更新会降低先前获得的能力。在本文中，我们介绍了HarnessEvolve，一个从参考轨迹中学习以实现可靠智能体自我进化的自我进化框架。HarnessEvolve将执行智能体与进化流程解耦，将执行、评估、优化和门控分配给独立的智能体模块，从而实现可泛化和稳定的装备改进。具体而言，HarnessEvolve通过生成参考轨迹（在给定真实答案时产生的执行路径）并将失败执行与参考轨迹对齐以提取错误信号来克服信用分配失败，这些错误信号经过聚类以揭示系统性失败模式。为防止捷径学习和灾难性遗忘，候选装备更新必须通过两道门：一道质量门，用于过滤数据泄漏和提示膨胀；一道性能门，若每个更新在当前批次上有所改进且不降低最近批次的性能则接受该更新，并在保留集上做周期结束验证以选择表现最佳的被接受智能体快照。我们在涵盖开放领域和企业场景的多个基准上，使用不同模型和智能体框架进行了大量实验。结果表明，HarnessEvolve在所有基准和设置中均持续优于最先进的基线，证实了其在任务领域上的可靠性。

## Abstract
Self-evolving agents advance toward autonomy by optimizing their harness---prompts, skills, tools, and execution logic---based on environmental feedback. This paradigm, however, is hampered by three challenges: \textit{credit assignment failure}, where terminal success/failure feedback makes it ambiguous which step caused the error; \textit{shortcut learning}, where agents memorize task-specific patterns rather than acquire generalizable capabilities; and \textit{catastrophic forgetting}, where unguarded updates degrade previously acquired competence. In this paper, we introduce HarnessEvolve, a self-evolving framework that learns from reference trajectories to achieve reliable agent self-evolution. HarnessEvolve decouples the execution agent from the evolutionary pipeline, assigning execution, evaluation, optimization, and gating to independent agent modules, enabling generalizable and stable harness improvements. Specifically, HarnessEvolve overcomes credit assignment failure by generating reference trajectories (execution paths produced when given the ground-truth answers) and aligning failed executions against them to extract error signals, which are clustered to reveal systematic failure patterns. To prevent shortcut learning and catastrophic forgetting, candidate harness updates must pass two gates: a quality gate that filters data leakage and prompt bloat, and a performance gate that accepts each update if it improves on the current batch without degrading recent batches, with epoch-end validation on a held-out set selecting the best-performing accepted agent snapshot. We conduct extensive experiments on several benchmarks spanning open-domain and enterprise scenarios, using different models and agent frameworks. Results demonstrate that HarnessEvolve consistently outperforms state-of-the-art baselines across all benchmarks and settings, confirming reliability across task domains.

  - **捷径学习（Shortcut Learning）**：智能体倾向于把任务答案或过多任务特例硬编码进 harness，导致数据泄漏（data leakage）和提示膨胀（prompt bloat），看似准确率提升但并未获得可泛化能力；
  - **灾难性遗忘（Catastrophic Forgetting）**：每次更新只针对当前批次数据，可能破坏已习得的旧能力，导致多轮更新后整体性能退化。
- 整体含义：论文认为上述挑战不能靠设计另一种迭代式提示优化算法来解决，而需要系统级的架构变革——把执行与优化解耦，通过参考轨迹引导错误归因，并用多重门控机制保证更新质量的稳定性。

## 2. 方法论：核心思想、关键技术细节与流程
### 核心思想
- 提出 **HarnessEvolve**：让智能体从“给定真实答案时产生的参考轨迹（reference trajectories）”中学习。
- 解耦为四类独立智能体模块：执行智能体（$A_{exec}$）、评估智能体（$A_{eval}$）、优化智能体（$A_{opt}$）、门控智能体（$A_{gate}$），使优化过程可审计且不易被执行智能体操纵。

### 关键流程（按 batch 驱动循环）
1. **执行阶段**：用当前 harness 在训练批次 $B_j$ 上运行任务，产生轨迹；同时利用“问题 + 真实答案”生成参考轨迹。
2. **评估阶段**：
   - 评估执行准确率，收集失败轨迹集合；
   - 验证参考轨迹的“真实性”，防止智能体直接输出已给的答案而跳过工具调用等合法推理链。
3. **诊断与聚类（算法 1）**：
   - 将失败轨迹与参考轨迹对齐，找到“第一个分歧点”（first divergence point），即最靠前的动作偏差，作为根本原因；
   - 若无参考轨迹则退化为仅对失败轨迹做单轨迹分析；
   - 产生结构化错误信号 $F_i=(s_i, m_i, h_i)$（严重度、错误原因、修复提示）；
   - 按错误原因 $m_i$ 聚类，得到系统性失败模式；聚类时强调根因优先，并保护长尾（保留单样本簇）。
4. **候选生成**：优化智能体基于聚类结果对 harness 中的文件（技能、脚本、提示、工具描述、执行逻辑）提出修改，生成候选更新集合 $\Delta_{harness}$。
5. **质量门（Quality Gate）**：
   - 检查数据泄漏（LLM-as-judge，分数阈值 $\eta_{leak}$）；
   - 检查提示膨胀（新增的上下文示例数阈值 $\eta_{blo}$）；
   - 不通过则退回优化智能体修改，最多 $T_{rev}$ 次修订，否则放弃更新。
6. **性能门（Performance Gate）**：
   - 构建候选智能体 $A_{candidate}$；
   - 要求在当前批次 $B_j$ 上准确率提升至少 $\delta$；
   - 同时要求最近的 $R$ 个批次上的准确率下降不超过容忍度 $\epsilon$，即防止能力回退。
7. **快照池与周期末选择**：
   - 通过的更新作为快照存入池 $\mathcal{V}$，并成为当前活动智能体；
   - 每轮 epoch 结束时，在验证集 $T_{val}$ 上选出最优快照作为 $A_{epoch}$；
   - 重复多个 epoch，直到达到最大 epoch 数或验证准确率连续 $P_{ep}$ 轮无提升。

### 关键参数示例
- 批次大小 $b=40$，最大训练轮数 $E=20$；
- 批次耐心 $P_{batch}=10$、epoch 耐心 $P_{ep}=5$；
- 重放缓冲大小 $R=2$，改善边际 $\delta=0.0$，退化容忍度 $\epsilon=0.025$；
- 数据泄漏/膨胀阈值分别为 $\eta_{leak}=0.8$、$\eta_{blo}=5$。

## 7. 优点
1. **系统级架构创新**：将执行、评估、优化、门控解耦为独立模块，而非在同一个推理循环中既执行又自我修改，具有更高的可审计性，也减少“自我评价”偏差。
2. **参考轨迹解决信用分配**：利用真实答案引导生成成功路径，通过与失败轨迹对齐寻找首个分歧点，比单纯在失败轨迹上做反思更精细，有效缓解稀疏奖励下的归因模糊问题。
3. **双向门控设计**：质量门挡住“捷径学习”，性能门配合批量重放约束“灾难性遗忘”，快照池在验证集上做周期末择优，兼顾即时改进与长期稳定性。
4. **错误聚类与长尾保护**：不以严重度或距离阈值强行聚类，而是按错误原因聚类并保留单样本簇，从语义上避免把“系统性失败”与“罕见但关键”问题混为一谈。
5. **全面优化 harness 而非单一组件**：同时修改提示词、技能、脚本、工具描述和执行逻辑，相比只优化 skill.md 的 SkillOpt 有更大提升空间。
6. **跨框架迁移实验有价值**：把优化后的技能迁移到四个不同框架上验证，增强了“学到的是可泛化知识”这一结论的说服力。

## 8. 不足与局限
1. **依赖真实答案**：参考轨迹生成需要 ground-truth answer，这导致它并不适用于没有标准答案、无法预知成功路径的真实开放任务；落地场景中收集参考轨迹的成本很高。
2. **算力开销未报告，成本不透明**：论文没有说明参考轨迹生成

3. **短期收益与开源数据集上提升幅度有限的矛盾**：在部分开源 benchmark（如 SpreadsheetBench 76.4% vs. SkillOpt 74.6%，仅提升约 1.8 个百分点）上优势并不显著，可能限制其在已经高度优化场景中的边际价值判断。
4. **没有公平性/奖励模型讨论**：质量门中的“数据泄漏检查”依赖 LLM-as-judge，但正文没有给出该评判模型的具体型号、一致性校验或错误率，这使质量门的可靠性缺乏直接证据；若该 judge 本身误判，反而可能过滤掉有效更新。
5. **对参考轨迹的“真实性校验”不够具体**：文中提到“防止智能体直接输出已给答案而跳过工具调用等合法推理链”，但没有说明绕过该风险的具体校验算法或消融验证，容易被针对性攻击（如先伪造工具调用再输出答案）。

7. **快照池策略的验证集开销与过拟合风险**：周期末在验证集 T_val 上选择最优快照，但没有明确限制验证集使用的次数；如果多次 epoch 反复在同一个验证集上做选择，可能造成隐式验证集过拟合，最终报告数字偏高。

- **学术贡献的实质在于将“隐式反思”转化为“结构化、有根据的 Harness 工程更新”**：该论文的方法论价值不在于提出更强的大模型推理算法，而在于设计了一套可追溯、可迭代、可门控的自进化闭环系统。参考轨迹对比 + 首个分歧点定位 + 聚类 + 双门控，这一流水线在工程实践中具有较高的可操作性和研究延展性。
- **在实验科学严谨性上处于中等水平**：论文覆盖了多个领域与框架，并通过消融展示了各组件的必要性，但缺少统计显著性说明、算力开销分析和与更完整强基线（Self-Harness / AHE）的直接对比，导致结论在强基准面前的竞争力还不够硬。
- **应用前景判断**：该方法非常适合企业内“有条件收集 ground-truth 的垂直业务场景”，如本论文展示的云核心网/无线网问答；但离“完全自主、无需人工标注答案”的通用 agent 自进化仍有一段距离。因此更准确的定位是：面向特定业务域的**半自主 harness 自进化方案**。

## 10. 可借鉴的改进方向（供后续研究参考）
- 用过程奖励模型（PRM）代替基于真实答案的参考轨迹，缓解对 ground-truth 的依赖；
- 将参考轨迹生成融入执行过程（如多路径采样后自洽筛选），降低推理成本；
- 引入按难度分层的批次采样，让性能门的 δ/ε 阈值对难度波动更鲁棒；
- 对验证集做多次选择时的泛化保护，比如在最终报告上使用嵌套验证或早停加 Holdout；
- 将质量门的 LLM-as-judge 替换/增强为规则、可验证指标与小型专用判别模型的组合，提升门控的确定性与可审计性。

**总结一句话**：HarnessEvolve 是一套结构完整、工程导向很强、在内部数据上表现优异的 harness 自进化框架；其在解决信用分配、捷径学习与灾难性遗忘三方面提出的系统级思路尤其值得借鉴，但其依赖真实答案、算力开销不透明、实验对比不完整等问题，使其尚不足以支撑“通用智能体完全自进化”这一宏大叙事。
