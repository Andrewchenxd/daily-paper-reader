## 摘要
基于LLM的代理框架现已成为多步骤任务的个人助理。现有代理框架如OpenClaw通常遵循云代理部署模式，使用闭源云LLM作为骨干模型，这可能暴露用户隐私信息并产生重复的LLM调用成本。本地代理通过在用户控制的设备上部署前沿开源SLM来解决这些部署问题，但其任务效果仍远落后于云代理。通过诊断分析，我们揭示出使用前沿SLM骨干的本地代理效果有限，主要源于骨干模型规模有限导致的环境知识缺失，包括环境规则和操作流程。为了以非参数化、上下文高效且无需专家编写的方式补充此类知识，我们提出了SkillSmith，一种云-本地代理协作框架，使用技能作为上下文高效的知识载体，从云代理任务探索中自动构建技能，并利用本地代理执行反馈进化技能，以增强冻结的本地代理。在每日代理任务数据集AppWorld和WorkBench上的实验表明，自动生成的技能使配备Qwen3.6-27B(SLM)的本地代理达到了与使用前沿LLM的云代理相当的任务效果，优于最强的非参数基线，在AppWorld-Normal上将每个任务的平均操作数从36.1降至9.9，并且无需重新运行技能构建即可泛化到其他SLM骨干模型。

## Abstract
LLM-based agent frameworks now act as personal assistants for multi-step tasks. Existing agent frameworks such as OpenClaw commonly follow the Cloud Agent depolyment mode using closed-source cloud LLMs as backbone model, which may expose private user information and incur repeated LLM-calling costs. Local Agents address these deployment concerns by depolying frontier open-source SLMs on user-controlled devices, but their task effectiveness still lags far behind Cloud Agents. Through diagnostic analysis, we reveal that the limited effectiveness of Local Agents with frontier SLM backbones mainly comes from missing environment knowledge caused by limited backbone model scale including environment rules and operation procedures. To supply such knowledge non-parametrically, context-efficiently, and without expert authoring, we present SkillSmith, a Cloud--Local Agent collaboration framework that uses Skill as a context-efficient knowledge carrier, automatic constructs Skill from Cloud Agent task exploration and evolves Skill using Local Agent execution feedback to enhance a frozen Local Agent. Experiments on daily agent task datasets AppWorld and WorkBench show that the automatically generated Skill enables the Local Agent with Qwen3.6-27B(SLM) to achieve task effectiveness comparable to Cloud Agents with frontier LLMs, outperform the strongest non-parametric baselines, reduce average actions per task from 36.1 to 9.9 on AppWorld-Normal, and generalize to other SLM backbone models without rerunning Skill construction.

## 论文总结

### 一、核心问题与研究动机

- **研究背景**：现有主流 LLM Agent 框架（如 OpenClaw）采用云部署模式，将闭源云 LLM 作为骨干模型，每次执行步骤都需将本地任务上下文上传到云端，存在用户隐私泄露风险和重复调用成本。相比之下，本地部署代理（Local Agent）在用户设备上运行开源边缘模型，能降低隐私风险并节省推理成本。
- **关键矛盾**：本地代理虽具备部署优势，但其任务有效性远低于云代理。论文以 Qwen3.6-27B 为骨干的本地代理在 AppWorld-Normal、AppWorld-Challenge 和 WorkBench 上的通过率分别仅有 36.3%、28.1% 和 51.1%，远低于云代理的 90.5%~94.0%。
- **诊断分析核心发现**：
  1. 模型规模并不主导核心 agentic 能力。Qwen3.6-27B 在 SWE-bench、Terminal-Bench、QwenClawBench 等基准上与 Claude Opus 4.5 相当甚至超出。
  2. 本地代理失败的决定性因素是环境知识缺失（环境规则、操作流程）。对 36 个失败轨迹的抽样分析显示，91.7% 的失败源于缺失环境规则或操作流程，仅 8.3% 与能力不足有关。
  3. 非参数化注入环境知识即可显著改善表现（26/33 的知识型失败可被解决），无需微调模型。

### 二、方法论

- **SkillSmith 框架**：采用"云-本地代理协作"模式，以 **Skill** 为知识载体，通过云端代理自动构造并迭代进化技能，增强**冻结的本地代理**。
- **Skill 的形式化定义**：\( S = (M, R, C) \)，其中 M 为主手册 SKILL.md，R 为存储环境规则与操作流程的参考文件集合，C 为每个参考文件的加载条件。
- **核心机制——渐进式披露（Progressive Disclosure）**：执行时只加载任务相关的参考文件，使上下文成本取决于当前任务的实际需要而非整个知识库规模，有效缓解本地 SLM 上下文的限制。
- **问题形式化**：将离线技能学习建模为黑盒优化，目标是找到技能 \( S^\star \)，使冻结本地代理在目标任务分布上的期望通过率最大化；以 Cloud Agent \( G_c \) 作为文本层面的"优化器"，在每一轮迭代中根据 Local Agent 执行反馈（作为类梯度信号）更新技能。

- **两阶段流程**：

  1. **技能创建（Skill Creation）**：
     - **探索与反思**：Cloud Agent 执行代表性任务、获取评估反馈，将原始轨迹压缩为反思报告（含任务描述、压缩轨迹、评估结果、高效路径、遇到的坑、工具使用等）。
     - **创建初始技能**：通过三种云端代理角色（Cluster Agent 聚类任务、Distill SubAgent 提取可复用信号、Merge Agent 进行常识性筛选合并生成长度受限的初始技能 S₀），对不同应用/工具簇生成独立的参考文件。

  2. **技能进化（Skill Evolution）**：迭代执行 R 轮：
     - **执行与压缩**：Local Agent 携带当前技能执行训练任务，将失败轨迹与评估反馈压缩为紧凑的失败报告。
     - **技能进化**：Cluster Agent 对失败报告聚类，Analyze SubAgent 对每簇进行失败归因（技能未加载、技能指示不完整/错误、接近成功的粗心错误、不可修复因素），写出带优先级的修改说明；Merge Agent 在长度预算约束内合并冲突、按优先级应用编辑，得到新版本技能 \( S_i \)。
- **最终部署**：离线阶段选择验证集通过率最高的技能版本部署。在线服务阶段不含任何云 LLM 调用，所有数据留于本地。
