## 摘要
智能体日益依赖可复用技能来编码任务知识、工具使用流程和验证规则。现有的技能自我进化方法主要利用从当前任务中收集的执行轨迹来修订技能，而公共技能版本历史中积累的进化知识在很大程度上未被利用。我们的初步研究揭示了这两种来源之间的明显互补性：公共技能变更提供了可复用的进化先验，而轨迹则提供了基于当前任务的实证证据。受此启发，我们提出了VCE-Skill，它将嘈杂且特定于实现的公共技能变更提炼为可复用、结构化的版本变化经验，并自适应地将其与基础进化器从轨迹中提取的提议相融合，从而在利用外部经验的同时保留任务特定证据。大量实验表明，VCE-Skill提升了技能自我进化能力，平均得分提高了3.20至4.98分；迁移实验进一步表明，由此产生的技能实现了更强的跨模型迁移性能。我们的工作凸显了公共技能版本变更作为一种此前未被充分探索但有效的先验知识来源，并推动了轨迹驱动的技能自我进化。

## Abstract
Agents increasingly rely on reusable skills to encode task knowledge, tool-use procedures, and validation rules. Existing skill self-evolution methods primarily revise skills using execution trajectories collected from current tasks, leaving the evolution knowledge accumulated in public skill version histories largely untapped. Our pilot study reveals a clear complementarity between the two sources: public skill changes provide reusable evolution priors, whereas trajectories provide evidence grounded in the current task. Motivated by this, we propose VCE-Skill, which distills noisy and implementation-specific public skill changes into reusable, structured version-change experience and adaptively fuses it with trajectory-derived proposals from the base evolver, thereby exploiting external experience while retaining task-specific evidence. Extensive experiments demonstrate that VCE-Skill improves skill self-evolution, increasing mean scores by 3.20--4.98 points; transfer experiments further show that the resulting skills achieve stronger cross-model transfer performance. Our work highlights public skill version changes as a previously underexplored yet effective source of prior knowledge and advances trajectory-driven skill self-evolution.

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）智能体日益依赖可复用的“技能”（Skill）——一种文件系统化的能力包（含指令、脚本、配置等），用于编码任务知识与工具使用流程。技能并非一次定稿，而会随工具变化、任务分布偏移和失败累积而持续修订，即“技能进化”。
- **现有范式及其局限**：目前的技能自我进化（Skill Self-Evolution）遵循“执行→收集轨迹→诊断失败→修订技能”的轨迹驱动循环。这类方法完全依赖当前任务批次中收集到的执行轨迹，存在三个关键问题：
  - 轨迹质量不佳时难以提取可靠指导；
  - 当前执行未暴露的失败模式无法被覆盖；
  - 容易过拟合到有限的观测，遗漏广泛适用的更新知识。
- **核心问题**：公共技能版本历史（如 GitHub、ClawHub 上相邻版本间的变更记录）中积累了大量由人类维护者执行的进化知识，但这一来源是否能为轨迹驱动的技能自我进化提供互补的、超越轨迹本身的知识，以及如何将嘈杂、仓库特定的原始 diff 转变为可复用的进化指导，都是尚未解决的问题。
- **整体思路与贡献**：论文提出 **VCE-Skill**，首次系统地将“公共技能版本变更”作为外部先验知识引入技能自我进化，通过经验蒸馏将原始修改提炼为结构化“版本变化经验”（Version-Change Experience, VCE），并与轨迹驱动的自我提议进行自适应融合，从而同时利用外部可复用先验与当前任务的具体证据。

## 2. 方法论

### 2.1 核心思想

VCE-Skill 包含两个核心观察：
1. **初步研究（Motivation Study）**：对 400 个公共版本变更单元与 400 个轨迹派生变更单元，在统一的组件—意图—模式分类体系下进行比较，发现两者覆盖度高度互补——轨迹驱动的变更高度集中于指令修改，而公共历史覆盖更广的组件、意图和模式；反之，某些轨迹特有变更也无法由公共历史覆盖。这证明公共版本历史不能替代轨迹，但能补充轨迹。
2. **利用方式**：不能直接使用原始 diff，因为它们是细粒度、仓库特定的。必须经过两个阶段——**蒸馏为可迁移的进化指导**，以及**与轨迹提议的选择性融合**。

### 2.2 技术流程

VCE-Skill 分为两个阶段：

**阶段一：经验蒸馏（Experience Distillation）**
- **变更抽象（Change Abstraction）**：将同一技能的历史版本按时间排序，对每对相邻版本做 diff，分解为原子“更新事件”（update event）：`u_j = ⟨d_j, {c_j}, o_j, i_j⟩`，其中 `d_j` 为原始 diff 片段，`{c_j}` 为受影响的组件（指令、脚本、参考文档、配置等），`o_j` 为语义操作（如“增加输入存在性检查”），`i_j` 为更新意图（如“缺少必要输入时防止执行”）。
- **经验生成（Experience Generation）**：跨三个抽象层级组织经验：
  - **更新模式（Update Pattern）**：在单个技能版本历史内，将组件、操作、意图相关的事件分组，去除仓库特定细节，归纳为可迁移的更新策略；
  - **进化洞见（Evolution Insight）**：综合该技能历史中的多个更新模式，表征该技能反复出现的更新策略；
  - **领域洞见（Domain Insight）**：将同一任务领域内多个技能中共有的进化洞见进一步泛化，得到跨技能可迁移的优化原则。
- 所有层级的条目共同构成**经验库（Experience Bank）B**，供在线优化阶段检索。

**阶段二：自适应经验注意力优化（Optimization with Adaptive Experience Attention）**
- **经验选择（Experience Selection）**：在第 t 轮迭代，构造选择上下文 `z_t = Context(T, S_{t-1}, f_{t-1})`（含目标任务 T、当前技能 S_{t-1}、上一轮统一反馈 f_{t-1}），用 LLM 选择器从经验库中选取最多 K 条相关经验，聚合成外部经验指导 `p_t^exp`。
- **自提议生成**：并行地，基础进化器（Base Evolver）根据当前技能及其执行轨迹 τ_{t-1} 生成轨迹驱动的自提议 `p_t^self`。
- **注意力融合（Attention Fusion）**：分配源级权重 `λ_exp + λ_self = 1`（初始为 0.5，裁剪于 [0.3, 0.7]），由 LLM 融合器按权重作为“提示级信任指令”将外部经验和自提议融合为增强提议 `p_t^enh`，每个编辑保留来源标识（EXP-k / SELF-k）。
- **技能优化**：技能优化器依据 `p_t^enh` 对技能束进行修订，得到新技能 S_t。
- **适应反馈（Adaptation Feedback）**：执行 S_t 获得新轨迹用于下一轮基础进化器；同时，将实际技能变更与带来源标识的候选编辑进行语义比对，计算源反馈：
  - `f_S^t = (1/n_t) Σ a_{t,k}`，其中 a_{t,k} ∈ {−1, 0, +1}，+1 表示外部经验支持的候选编辑被实现，−1 表示自提议支持的编辑被实现，0 表示未实现或混合来源；
  - 验证反馈 `f_V^t = +1（验证集性能提升）或 −1（未提升）`；
  - 统一反馈 `f_t = f_V^t · f_S^t`；
  - 下一轮权重更新为 `λ_exp^{(t+1)} = clip(λ_exp^{(t)} + η·f_t, 0.3, 0.7)`，步长 η = 0.1。
- 正反馈使后续偏向外部经验，负反馈使后续偏向轨迹自提议，从而在整个进化过程中动态调整外部经验与本地证据的依赖关系。

### 2.3 与其他方法的关系

VCE-Skill 是**基础进化器的即插即用增强模块**：它不改变基础进化器的执行、诊断、评估、保留与停止逻辑，只替换“提议构造”环节，将融合后的增强提议传回原生更新流程。论文适配了 EvoSkill、SkillClaw 和 SkillOpt 三种基础进化器。

## 6. 主要结论与发现

1. **公共版本历史与轨迹驱动进化存在互补覆盖**：动机研究显示，公共变更的组件、意图和模式分布更广泛，而轨迹变更高度集中于指令类别；双方也存在各自独有的类别，说明公共历史无法替代轨迹证据，但能补充轨迹证据之外的进化知识。
2. **VCE-Skill 显著提升技能自我进化**：在所有 3 个基础进化器 × 4 个模型 × 5 个基准的组合中，VCE-Skill 均带来正增益，平均分提升 **3.20–4.98 分**。
3. **经验蒸馏和自适应注意力均有独立贡献**：去除蒸馏会导致性能低于原始基线（说明蒸馏对去除无关实现细节至关重要）；去除自适应注意力虽通常仍优于基线，但一致低于完整方法（说明固定等权融合不如动态调整有效）。
4. **跨模型迁移能力更强**：VCE-Skill 进化的技能在全部 12 个有向源—目标模型对上均优于无 VCE 的技能，平均提升 5.15–6.19 分（总体平均 5.56 分），甚至超过同设置下的同模型提升，显示外部经验抑制了源模型特定行为、强化了通用问题求解原则。
5. **公共技能版本历史是一种此前被忽视但有效的先验知识来源**，可无缝融入现有轨迹驱动的技能自我进化框架。

## 7. 优点

- **问题新颖且动机扎实**：首次系统地将软件工程中版本历史挖掘的思想迁移到 LLM 智能体技能进化领域；动机研究设计了统一的“组件—意图—模式”分类协议，直接回答了“公共历史是否提供轨迹之外的知识”这一关键问题。
- **方法设计合理、模块化强**：VCE-Skill 与基础进化器解耦，只需薄适配层即可增强不同进化框架；经验库的三层抽象（模式→进化洞见→领域洞见）设计使知识从仓库特定走向领域通用，逐步去除实现噪声。
- **自适应用例设计细致**：注意力权重由“来源归因 + 验证性能”双重反馈驱动，既能识别实际变更主要来自哪个知识源（来源归因），又能感知该变更是否真正有效（验证反馈），四个象限（改进/非改进 × 外部/自提议）对应清晰的权重调整方向。
- **人工审计意识强**：针对所有依赖 LLM 判断的环节进行了大规模人工审计，量化了判别可靠性，而非默认 LLM 输出为真，增强了流程的可信度。
- **提示工程设计严谨**：附录提供了完整的提示词，约束 LLM 输出必须附带证据来源 ID、禁止捏造、要求空列表规避弱证据等，体现了工程上的系统化考虑。

## 8. 不足与局限

- **报告不完整**：正文表 1 仅展示平均分与配对比比较，未提供标准差、置信区间或显著性检验，读者无法评估提升的稳健性和统计意义。
- **算力开销不透明**：未报告各实验配置的具体运行时间、API 调用次数或成本对比，仅提供 token 估算，难以评估方法在资源受限环境中的实际可行性。
- **LLM 判断的级联误差风险**：VCE-Skill 的蒸馏、选择、融合、归因四个环节均依赖 LLM 判断，虽然逐环节人工审计 HAR 较高（86.5%–100%），但级联误差（早期蒸馏错误传递到后期优化）未被端到端评估。
- **经验库构建成本与覆盖偏差**：经验蒸馏依赖人工为每个基准挑选最匹配的 5 个公共技能；这一过程可能引入领域覆盖偏差，且面向新任务领域时需重新构建，通用化流程未详细说明。
- **外部经验误导风险处理有限**：虽然负反馈会将权重移向自提议，但注意力被裁剪在 [0.3, 0.7] 之间，即外部经验权重最低仍达 0.3，无法完全屏蔽有害经验；论文未分析外部经验显著有害于当前技能时的行为边界。
- **应用限制**：方法的实用性依赖公共技能版本历史的可用性与质量；对小众、私有不公开或历史稀少的技能领域，其收益可能受限。
- **远期效果未评估**：实验约 20 轮进化，未展示更长进化跨度下经验自适应是否会出现权重振荡、经验过时或灾难性遗忘等问题。
